# Examples

Worked walkthroughs of using the harness. These are illustrative: they deliberately avoid naming a
language, framework, or package manager, because the harness must not assume one.

| File | Shows |
| --- | --- |
| `adopting-an-existing-project.md` | Installing the harness into a project that already has code, and filling in its `CLAUDE.md` from evidence |

## What belongs here

- End-to-end walkthroughs of the workflow on a realistic task.
- Filled-in examples of the templates, clearly marked as illustrative.
- Adaptations for a particular kind of project (monorepo, library, service), once one has actually
  been done.

## What does not

- Anything that hardcodes a stack, a command, or a tool as if it were the default.
- Copies of skill or agent content — link to the source instead, so the example cannot drift.
- Transcripts kept as trophies. An example earns its place by teaching a decision, not by showing a
  success.
